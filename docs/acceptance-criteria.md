# 驗收標準

> 對應評分項 2。AC 編號對齊 REQ 編號;每條 AC 都要有對應測試案例 TC-xx(見 test-plan.md)。

| 編號 | 驗收條件 | 對應需求 |
|------|----------|----------|
| AC-01a | 點擊導覽列 1-4 可切換頁面,當前頁高亮 | REQ-01 |
| AC-01b | 按「90 秒導覽」自動走完四頁,總時長 90±5 秒;可隨時暫停 | REQ-01 |
| AC-01c | 按「重設」回到第 1 頁且 slider 歸零 | REQ-01 |
| AC-02a | 第 1 頁全站綠燈;第 2 頁三號機台黃燈;第 4 頁紅轉綠(已處置) | REQ-02 |
| AC-02b | 點選/鍵盤 Enter 任一站點圓點,可顯示該站當前訊號文字說明,不只靠顏色 | REQ-02 |
| AC-03a | 診斷卡六格齊全,證據至少 3 條且每條含具體時間點,顯示知識依據與人工狀態 | REQ-03 |
| AC-04a | slider 0-30 分鐘,損失金額即時更新且與公式一致 | REQ-04 |
| AC-04b | 損失公式:延遲分鐘 × 每分鐘產量 × 缺陷率差 × 單位不良成本 | REQ-04 |
| AC-05a | 390×844 直向可完整操作四頁與 slider,無橫向捲動 | REQ-05 |
| AC-06a | 斷網 + file:// 開啟 dist-offline/index.html 可完整展示 | REQ-06 |
| AC-06b | 瀏覽器 Network 面板無 runtime 外部請求 | REQ-06 |
| AC-07a | 情境資料缺欄位時顯示提示文字,不白屏,且其餘頁面不受影響 | REQ-07 |
| AC-08a | 第 2 頁需列出規則命中明細表(訊號/觀測值/門檻/權重/是否觸發)、計分公式與感測器品質係數,評分數字可被回推驗算 | REQ-08 |
| AC-09a | 至少提供 4 種情境(確診異常/正常巡檢/感測缺值/疑似誤報),可由 UI 切換 | REQ-09 |
| AC-09b | 情境資料一律經 runtime schema 驗證,不依賴 TS 對單一 JSON 字面量的型別推斷 | REQ-09 |
| AC-10a | 診斷卡「內容審核」與「現場處置確認」為兩個獨立可視欄位;決策頁需顯示復機驗證狀態、目標良率與重開案條件,不得單純以「已處置」文案暗示已完全恢復正常 | REQ-10 |
