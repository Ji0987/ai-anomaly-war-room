# Kickoff 一頁式摘要

> 給第一次接觸這個專題的人。看完這頁,你就知道我們要做什麼、為什麼做。

## 一句話定位

AI 生產異常戰情室:一個完全離線的網頁展示,90 秒走完「看見異常 → 找出原因 → 決定怎麼處理 → 算出不處理的代價」。

## 事故情境(我們展示的故事)

二號產線三號機台換料後,模具溫度從 62°C 一路漂移到 71°C,良率從 98% 掉到 91%。現場人員要回答三件事:哪裡出錯?現在先做什麼?晚處理十分鐘會多損失多少錢?

## 為什麼做這個

- 老師範例主題第一條就是「設備異常分析助手」——這題目跟課程要求完全對上
- 產線異常發生時,現場人員要在多張報表/系統間切換,追因依賴資深師傅經驗;師傅不在場,新人就卡住
- 同時符合「2026 台灣數創大賞」報名資格,可另投企業特別獎

## 五段決策閉環(核心邏輯)

**場域感知 → 知識治理 → 戰情室追因 → 人員決策 → 損失量化**

> 90 秒不是比演算法算得快,是 90 秒內走完整段決策流程。

## 四個展示頁面

1. **正常基線|全域感知** — 良率 98%,一切正常
2. **異常事件|邊緣告警** — 溫度/振動/電流出現異常,三號機台亮黃燈
3. **AI 老師傅診斷卡** — 根因/信心/證據/知識依據/建議處置/人工確認狀態
4. **根因閉環** — 揭曉真正原因 + 拉 slider 看「晚處理幾分鐘,多虧多少錢」

## 90 秒成功標準

按下「90 秒導覽」,四頁自動播放完畢(90±5 秒),中途可暫停、可重設。現場斷網也要能跑(展示用離線單檔 HTML)。

## 這個月不做的事

- 不做硬體/感測器(MCU 支線已評估,零件時程風險太高,取消)
- 不做後端、資料庫、登入、即時 API 呼叫(AI 診斷卡是預先生成、人工審核過的,不是現場即時問 AI)
- 不宣稱已完成真正的地端部署,不寫任何特定企業產品名稱
- 送審/簡報一律不出現學校、姓名、企業名稱或標誌(數創大賞匿名規範,提前養成習慣)

## 大致里程碑(約 4 週,可依實際調整)

- 第 1 週:走完核心流程的最小切片,開出 Draft PR
- 第 2 週:核心功能完成,審查後合併進 `dev`
- 第 3 週:整合測試(docs/test-plan.md 全表)、離線版驗證
- 第 4 週:demo 凍結(打 `demo-final` tag)、彩排、繳交
