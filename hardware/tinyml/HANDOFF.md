# 交接文件——現在的題目是什麼、需要什麼

> **2026-08-22 全面重寫**：D3 車版本（機械手臂裝在四輪車體上）已被取代。使用者當天拆下 MeArm、放棄 D3 車體與 PS2，題目收斂成獨立夾爪致動器的邊緣安全證據包。完整技術細節與逐輪決策過程見 [`WARROOM-2.0-PLAN.md`](WARROOM-2.0-PLAN.md)（這份是權威來源，本文件是給你快速抓重點用的）。

## 這是什麼、跟主線的關係

「AI 生產異常戰情室」的正式評分交付是 `src/` 底下這個完全離線的網頁 demo。`hardware/tinyml/` 這個目錄原本是另外用 git worktree 切出來的**個人加碼展示**，2026-09-01 已合併進 `dev`/`main`，跟網頁 demo 並存在同一個 repo 裡（worktree 已移除，現在單一工作目錄即可看到兩邊）。這條線本身仍不動 `src/`、`docs/`、`.github/` 既有內容。

## 現在的題目（一句話）

**用一支獨立的 MeArm 機械手臂夾爪，做電流限制式自適應夾持（迴歸）＋過載卡料偵測（分類）。**

夾爪（MG90S）閉合時，用電流訊號學習/調整不同物體該用多大的夾持角度增量，過載時自動煞車。溫度當輔助佐證（GY-91 振動因硬體故障已 descope）。語音下指令＋筆電端 VLM 選物這條展示層 2026-09-07 已明確取消，不在本次專題範圍內。

MeArm 已從 D3 車拆下獨立運作，不再用四輪車體、Uno、Emakefun 驅動板、PS2 遙控。**現在這版是 2026-08-22 三輪 Fable×Sol 討論（agent-bridge 信箱 MSG 44-49）收斂後的定案**，除非物理驗證證明行不通，不要再回頭懷疑。

## 要用什麼硬體（已有 vs. 還要買）

### 已經有、直接用

| 元件 | 角色 |
|---|---|
| MeArm 機械手臂本體（4 顆 MG90S） | 被監控/控制資產，已從 D3 車拆下獨立運作 |
| ESP32-S3 MiniBoard | **唯一控制器**：直接驅動 PCA9685、讀取所有感測器、接筆電序列指令，取代 Arduino Uno |
| GY-91（振動計） | 貼**腕部/夾爪剛性基座**（不貼活動指片，見 WARROOM-2.0-PLAN.md「感測配置細節」） |
| INMP441（麥克風） | 只做接觸/掉落/卡料的聲學佐證特徵，**不做語音指令輸入** |
| 筆電（USB webcam＋麥克風＋喇叭） | 語音辨識、VLM 視覺、TTS 回報全部在此執行 |

### 還需要買/做（大幅縮減）

| 項目 | 規格 | 備註 |
|---|---|---|
| **ACS712-5A 電流感測模組 ×1**（大幅縮減，D3 車版本規劃過 4 顆） | 5A 版本 | 只接夾爪伺服，核心閉環的唯一必要感測器 |
| 通用 PCA9685 舵機驅動板 ×1 | 標準 16 通道 breakout | 取代 Emakefun MotorDriverBoard V5.2 |
| 伺服延長線 ×1 | 母對公 3 芯 | 非破壞式串接電流感測器到夾爪伺服 |
| USB webcam ×1 | 一般解析度，可固定俯視 | 取代 OV5640 做 VLM 視覺輸入，兼差當異常證據照 |
| DS18B20 溫度探頭（選配，最多 1 顆） | TO-92 封裝 | 只貼夾爪伺服，角色是熱累積佐證非判定主力 |

### 已經停用（不用管）

Arduino Uno R3、Emakefun MotorDriverBoard V5.2、D3 車體與 4 顆輪 TT 馬達、TB6612FNG、PS2 遙控與接收器、`PS2X_lib`（ESP32-S3 無正式支援，查證見 WARROOM-2.0-PLAN.md）、原規劃的 4 顆 ACS712/4 條延長線/4 顆 DS18B20（單夾爪架構下不需要）、OV5640 的即時串流角色（若保留只做單張證據照）。

## 現在進度到哪、下一步做什麼

**已完成**：
- G0（安全與供電，D3 車版本的成果，部分仍可參考——如板載開關可切斷動力的原則）
- **H1（韌體整合）**：`firmware/eep_gripper_h1/eep_gripper_h1.ino` 已整合 PCA9685 驅動、ACS712/GY-91/DS18B20 讀取、序列指令通道、本地安全逾時。指令集：`start`/`stop`/`status`（JSON，給資料擷取工具用）、`show`/`jog`/`center`/`home`/`release`/`hold`/`guard`/`ack`（人類可讀文字，給互動校正用）；`jog` 同時支援 `jog:<軸>:<+/-N>` 與短指令（`s+10`/`t-10`/`l+10`/`p-10`）。
- **H2（伺服校正）**：四軸 min/max 已收斂為 635-3003µs、原點 swap 1758µs／stretch/lift 1221µs／paw 2539µs，皆為實測校正值（`SERVO_MIN_US`/`SERVO_MAX_US`/`SERVO_HOME_US`）。
- **H2.5（即時儀表板）**：`live-dashboard/index.html`，伺服滑桿即時控制、電流(A)+溫度趨勢（大數字+sparkline）、獨立控制頁（手機用）、H3 資料蒐集面板。**2026-09-07 大幅精簡**：GY-91 實機 I2C 完全無回應（`who_am_i:0`，根因排查未果），正式 descope 三軸加速度波形、3D 運動學（FK/IK）視窗、運動學參數面板；模擬模式也一併移除（判斷「保留一條不會再維護的假資料路徑」風險大於好處）。細節見 WARROOM-2.0-PLAN.md「即時儀表板」節。
- **H3（核心資料收集＋分類器）✅ 2026-09-06/07 完成**：真實硬體收集 30 筆 trial（`NORMAL_GRIP`/`OVERLOAD_JAM`/`NO_CONTACT`各 10），訓練決策樹（`tools/train_h3_classifier.py`，leave-one-out 準確率 80%），**已直接寫進韌體做即時判斷**：每次 `stop` 且串流滿 2 個視窗，韌體自動分類並在偵測到 `OVERLOAD_JAM` 時自動 release、鎖定 jog/center 指令直到操作者送 `ack`（新增的優先權機制，見下方）。儀表板同步跳出醒目的彈出視窗＋log 提示。已知限制：`OVERLOAD_JAM` 召回率僅 60%（10 次卡住漏 4 次），門檻是這批資料 fit 出來的，換感測器/分壓/環境需重新收資料重跑訓練工具。圖表見 `data/analysis/h3_*.png`，細節見 WARROOM-2.0-PLAN.md「H3 資料收集與分類器」節。
- **安全優先權機制**（2026-09-07 新增）：手動伺服控制（滑桿/jog）跟分類器的自動安全 release 之間定了優先級——auto-release 觸發後，jog/center 一律被拒絕直到操作者送 `ack` 確認，避免滑桿還在拖曳時把剛被安全釋放的軸重新啟動。H3 自動化採集流程（`runCaptureTrial()`）在每筆 trial 結束都會自動送 `ack`，不影響連續採集。

**下一步**：
1. **韌體待重新燒錄＋真機驗證**：本次新增的即時分類器＋安全優先權機制（`ack`/latch）都是這個 session 寫的，**還沒有在真機上燒錄測試過**，需要用 Arduino IDE 重新燒錄 `eep_gripper_h1.ino`，並實際夾一次阻擋物確認分類+自動 release+鎖定/`ack` 解除都如預期運作。
