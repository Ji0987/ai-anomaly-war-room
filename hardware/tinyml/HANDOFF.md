# 交接文件——現在的題目是什麼、需要什麼

> **2026-08-22 全面重寫**：D3 車版本（機械手臂裝在四輪車體上）已被取代。使用者當天拆下 MeArm、放棄 D3 車體與 PS2，題目收斂成獨立夾爪致動器的邊緣安全證據包。完整技術細節與逐輪決策過程見 [`WARROOM-2.0-PLAN.md`](WARROOM-2.0-PLAN.md)（這份是權威來源，本文件是給你快速抓重點用的）。

## 這是什麼、跟主線的關係

「AI 生產異常戰情室」的正式評分交付是 `src/` 底下這個完全離線的網頁 demo。`hardware/tinyml/` 這個目錄原本是另外用 git worktree 切出來的**個人加碼展示**，2026-09-01 已合併進 `dev`/`main`，跟網頁 demo 並存在同一個 repo 裡（worktree 已移除，現在單一工作目錄即可看到兩邊）。這條線本身仍不動 `src/`、`docs/`、`.github/` 既有內容。

## 現在的題目（一句話）

**用一支獨立的 MeArm 機械手臂夾爪，做電流限制式自適應夾持（迴歸）＋過載卡料偵測（分類）。**

夾爪（MG90S）閉合時，用電流訊號學習/調整不同物體該用多大的夾持角度增量，過載時自動煞車。溫度與腕部振動當輔助佐證。語音下指令＋筆電端 VLM 選物是時間允許才做的展示層，不是核心閉環。

MeArm 已從 D3 車拆下獨立運作，不再用四輪車體、Uno、Emakefun 驅動板、PS2 遙控。**現在這版是 2026-08-22 三輪 Fable×Sol 討論（agent-bridge 信箱 MSG 44-49）收斂後的定案**，除非物理驗證證明行不通，不要再回頭懷疑。

## 要用什麼硬體（已有 vs. 還要買）

### 已經有、直接用

| 元件 | 角色 |
|---|---|
| MeArm 機械手臂本體（4 顆 MG90S） | 被監控/控制資產，已從 D3 車拆下獨立運作 |
| ESP32-S3 MiniBoard | **唯一控制器**：直接驅動 PCA9685、讀取所有感測器、接筆電序列指令，取代 Arduino Uno |
| GY-91（振動計） | 貼**腕部/夾爪剛性基座**（不貼活動指片，見 WARROOM-2.0-PLAN.md「感測配置細節」） |
| INMP441（麥克風） | 只做接觸/掉落/卡料的聲學佐證特徵，**不做語音指令輸入** |
| 筆電（USB webcam＋麥克風＋喇叭） | 語音辨識、VLM 視覺、TTS 回報全部在此執行 |

### 還需要買/做（大幅縮減）

| 項目 | 規格 | 備註 |
|---|---|---|
| **ACS712-5A 電流感測模組 ×1**（大幅縮減，D3 車版本規劃過 4 顆） | 5A 版本 | 只接夾爪伺服，核心閉環的唯一必要感測器 |
| 通用 PCA9685 舵機驅動板 ×1 | 標準 16 通道 breakout | 取代 Emakefun MotorDriverBoard V5.2 |
| 伺服延長線 ×1 | 母對公 3 芯 | 非破壞式串接電流感測器到夾爪伺服 |
| USB webcam ×1 | 一般解析度，可固定俯視 | 取代 OV5640 做 VLM 視覺輸入，兼差當異常證據照 |
| DS18B20 溫度探頭（選配，最多 1 顆） | TO-92 封裝 | 只貼夾爪伺服，角色是熱累積佐證非判定主力 |

### 已經停用（不用管）

Arduino Uno R3、Emakefun MotorDriverBoard V5.2、D3 車體與 4 顆輪 TT 馬達、TB6612FNG、PS2 遙控與接收器、`PS2X_lib`（ESP32-S3 無正式支援，查證見 WARROOM-2.0-PLAN.md）、原規劃的 4 顆 ACS712/4 條延長線/4 顆 DS18B20（單夾爪架構下不需要）、OV5640 的即時串流角色（若保留只做單張證據照）。

## 現在進度到哪、下一步做什麼

**已完成**：
- G0（安全與供電，D3 車版本的成果，部分仍可參考——如板載開關可切斷動力的原則）
- **H1（韌體整合）**：`firmware/eep_gripper_h1/eep_gripper_h1.ino` 已整合 PCA9685 驅動、ACS712/GY-91 讀取、序列指令通道、本地安全逾時。指令集：`start`/`stop`/`status`（JSON，給資料擷取工具用）、`show`/`jog`/`center`/`home`/`release`/`hold`/`guard`（人類可讀文字，給互動校正用）；`jog` 同時支援 `jog:<軸>:<+/-N>` 與 D3 校正工具風格的短指令（`s+10`/`t-10`/`l+10`/`p-10`）。
- **H2（伺服校正）**：四軸 min/max 已收斂為 635-3003µs（使用者用電源供應器電流讀值＋堵轉聲音實測校正，不是隨意數字，過程見 agent-bridge 信箱 MSG 51-58）。**四軸原點（home）已是真實校正值**：swap 1758µs、stretch/lift 1221µs、paw 2539µs。這兩組數字都寫在韌體常數裡（`SERVO_MIN_US`/`SERVO_MAX_US`/`SERVO_HOME_US`），不是佔位符。韌體同時已加上 DS18B20（選配，1-Wire，GPIO5）非阻塞讀取，未接探頭時 `ds18b20_ready` 就是 false，不影響其他功能。
- **H2.5（即時儀表板）**：`live-dashboard/index.html` 已完成三輪擴充——伺服滑桿控制、雙波形視窗（加速度／電流+溫度，頻譜圖已依需求移除）、FK+IK 3D 運動學視窗（公式對照 York Hackspace 官方原始碼核實，IK→FK 往返測試驗證自洽）、IMU 軌跡疊圖（ZUPT 零速校正，含座標系偏移換算）、獨立控制頁（手機用，同文件內視圖切換，不是另開分頁）、模擬模式、**H3 資料蒐集面板**(標籤化定步幅夾持試驗，JSON 匯出)。細節見 WARROOM-2.0-PLAN.md「即時儀表板」節。

**下一步**：
1. 使用者驗收儀表板（含拿真實硬體測試協定解析——目前只驗證過模擬模式與數學邏輯，沒有真實序列埠連線測試過）
2. H3（NORMAL_GRIP/OVERLOAD_JAM 資料收集）：採集面板已建置並在模擬模式驗證過完整流程，但**還沒接真實硬體跑過一次**——下一步是接上真機、驗收協定解析，然後才能開始收集真實訓練資料。

**還沒決定、不急著現在處理**：語音/視覺展示層（H5）的實際腳本內容、GY-91 振動特徵的兩段式窗格切分細節（整臂運動 vs 夾爪接觸）。

## 怎麼走到這裡（歷史脈絡，不影響現在的執行，想了解來龍去脈才需要看）

完整過程見 [`WARROOM-2.0-PLAN.md`](WARROOM-2.0-PLAN.md) 文末「怎麼走到這裡」一節與 agent-bridge 信箱 MSG 44-49。簡述：零件延遲觸發 MVP 降規模討論 → 使用者實體拆下 MeArm 直接跳過漸進降規模 → 放棄 PS2（ESP32-S3 相容性未經證實）→ 五分類框架收斂成二元過載偵測 → ML 任務從純分類改為分類+迴歸雙軌 → 語音/視覺全部交給筆電 → 否決 RUL 方向，確認多任務+多模態定位已經足夠有研究味。
